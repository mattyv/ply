# Plan — D7 replayable tests: the rendered cex test must assert the contract itself

Status: planned, not started. Target milestone: **M3**. Evidence base:
`tests/spike/FINDINGS.md` finding 3, ADR-0003 caveat 3 (cargo-kani 0.67.0 / CBMC 6.8.0).

## 1. Problem

Kani's generated playback test runs the real body only — contract closures are never
evaluated — so for an `ensures` violation it **passes**. Kani's promised "declined to
generate" warning did not appear in our run, so Ply cannot detect the case from Kani's
output. D7's red repair target must therefore be Ply's own rendered `#[test]`, and that
test must evaluate the postcondition explicitly so a violated contract is panic-shaped.
The naive rendering has its own trap, demonstrated by the spike: asserting
`result == x + 1` for `saturating_bump(255)` overflows *inside the assertion* and fails
with "attempt to add with overflow" — red for the wrong reason, message useless.

## 2. The artifact

One generated file per counterexample, placed **in-crate** in a `#[cfg(test)]`-gated
generated module (same mechanism as D2's `cfg(kani)` proof module — a generated file plus
one module declaration). In-crate placement is load-bearing: it is what lets the test
call private functions (spike item 1) and construct private-field witnesses that a
`tests/` integration test could never name. The §8 example path
`tests/ply_cex_pricing_quote_01.rs` changes accordingly (delta 5 below).

Worked example, the spike's own case (`pub fn saturating_bump(x: u8) -> u8` with
`#[ply::ensures(result == x + 1)]`, witness x = 255):

```rust
//! Generated by Ply — do not edit. Reproduces the counterexample for
//! `saturating_bump` found by check `bounded(1)` (diagnostic K0502).
//! This test fails until the function body or its contract changes, and
//! passes once they agree.

#[test]
fn ply_cex_saturating_bump_01() {
    // The failing input Kani found:
    let x: u8 = 255;

    let result = saturating_bump(x);

    // Contract under test: #[ply::ensures(result == x + 1)]
    // Arithmetic below is evaluated in i128 so the test can report the
    // broken promise instead of overflowing while checking it. (At this
    // input the contract claims 256, which u8 cannot even represent —
    // that unrepresentable claim is the defect.)
    let __ply_actual: i128 = result as i128;
    let __ply_claimed: i128 = (x as i128) + 1;
    assert!(
        __ply_actual == __ply_claimed,
        "Broken promise in `saturating_bump`: the function declares the postcondition \
         `result == x + 1` — a postcondition is the guarantee a function makes about \
         its return value. For the input x = 255 the function returned {__ply_actual}, \
         but the contract claims {__ply_claimed}. One of the two is wrong: fix the \
         body or fix the `#[ply::ensures]` line, and this test will pass. (K0502)"
    );
}
```

Properties, in order of importance:

- **Red for the right reason.** The widened comparison cannot overflow, so the only
  panic is the assertion, and its message states the contract, the input, and both
  values. `cargo test` output for this file *is* the diagnostic.
- **Newbie bar.** Plain sentence first, gloss of "postcondition" inline, the code in
  parentheses at the end. Message wording is exact-string golden-tested like all
  user-facing text.
- **Values are runtime-interpolated** (`{__ply_actual}`/`{__ply_claimed}`), never baked
  in as prose, so a partial fix cannot make the message lie. Generation-time knowledge
  (witness value, representability remark) lives in comments only.
- **Self-healing by design**: after a correct fix the expression evaluates true and the
  test passes — exactly the §9 oracle's FAIL-then-PASS shape.

## 3. Rendering rules (the hard parts)

The renderer's input is the already-validated §5.4a expression AST (the E0501
validator's parse — closed subset, so every case below is enumerable) plus typed witness
values decoded from Kani's concrete-playback byte vectors (Ply generated the harness, so
`kani::any()` order and types are known).

| Case | Treatment |
|---|---|
| `result` | `let result = f(args);` — subset identifiers only resolve to params/`result`, so no capture issues. |
| `old(expr)` (§5.4a) | `let __ply_old_N = <expr>;` evaluated **before** the call, substituted after — the exact machinery §5.4a already prescribes for test/fuzz harnesses. Shared code, not a second implementation. |
| `self` / methods | Receiver constructed from the witness as a literal (`let __ply_self = Counter { value: 255 };`) then `__ply_self.bump()`. In-crate placement makes private fields nameable. |
| Params moved by the call but referenced in `ensures` | **Re-materialize, don't clone**: Ply constructs the witness from source it rendered itself, so it can emit the identical literal twice (once for the call, once for the check). No `Clone` bound, no `Copy` bound, ever. |
| Integer arithmetic in the contract | Widen every arithmetic subexpression to `i128` (covers all integer types up to 64-bit, signed and unsigned). This is the spike-trap fix. |
| `u128`/`i128` operands | `i128` widening is unavailable; use `checked_*` ops. A `None` at the witness fails the test with its own honest message: "the contract's own arithmetic overflows at this input — the claimed value does not exist in the type". That is a rendering success, not a refusal: the message states the actual defect. Same treatment for `checked_div`/`checked_rem` (division by zero in the contract). |
| Compound booleans (`&&`, `\|\|`, `!`, `matches!`) | Decompose top-level `&&` into conjuncts; evaluate each; the message names the first false conjunct. When that conjunct is a comparison, print both sides; otherwise fall back to the generic message: contract text + inputs + `result` value + "this expression evaluated to false". Deterministic decomposition over a closed grammar — no per-case human judgment left in the loop (FINDINGS item 6–7's cost, paid once here). |
| `pure` helper calls | Called as-is — they are real Rust functions and in-crate placement sees them. Backstop below covers a helper that panics. |
| Non-`Debug` values in messages | Inputs are printed from their *rendered source* (Ply already has that string — it is `counterexample.inputs`). A non-`Debug` `result` degrades the message to the generic form; the test is still red for the right reason. |
| Panic anywhere inside contract evaluation (helper panic, anything the widener can't reach) | The whole check is wrapped in `std::panic::catch_unwind(AssertUnwindSafe(...))`. `Ok(true)` → pass; `Ok(false)` → the assertion message above; `Err(payload)` → fail with "the contract's own check crashed at this input (…payload…): the contract could not even be evaluated here, which itself means the contract or a pure helper it calls is wrong for this input". Never a bare `attempt to add with overflow`. |

### Refused cases

The expression side never refuses: §5.4a is closed and every construct in it is
runtime-evaluable Rust, with the widen/checked/catch_unwind ladder absorbing the
partiality. Refusals are all **input-side**:

1. A witness value with no stable Rust-source rendering (already D7/W0541).
2. A witness for a **foreign-crate** type whose fields are private and whose value is
   not reachable through any `pub` constructor — in-crate placement solves this for
   workspace types but not for types from crates outside the workspace (cross-crate
   callee params, ADR-0003 item 5).
3. A witness produced through a hand-written in-crate `kani::Arbitrary` whose raw field
   state is outside what any available construction path can express (ADR-0003 item 3b's
   coverage gap, seen from the other side).

**Diagnostic: reuse `W0541`, one code, with a structured `reason` field**
(`inputs_unrenderable` — cases 1–3; `expression_unrenderable` — reserved, currently
unreachable, kept so a future subset extension has somewhere honest to fail). Rationale:
every refusal means the same thing to the consumer — no `cargo_test` artifact, witness
input only — so a sibling code would add enum surface without a distinct action. The
W0541 message itself passes the newbie bar: it names the type, says why it cannot be
written down as source, and says what the agent still has (the exact input in
`counterexample.inputs` and the witness artifact).

## 4. Keep Kani's playback artifact? — yes, and it is nearly free

Recommendation: **keep it, stored always, described as witness input storage — never as
a reproduction.**

- The concrete values Ply needs for rendering come from the same expensive step
  (`--concrete-playback=print`, 18–23 s in the spike; detection alone is 0.05 s).
  Once that step has run, persisting the byte vectors as
  `target/ply/playback/<id>.json` costs nothing — the artifact is a byproduct, not a
  separate spend. The budget/lazy policy FINDINGS demands applies to the witness step
  as a whole (an M3 decision: a per-run witness budget with `--witnesses=all|N|none`),
  not to storing its output.
- It is the only *engine-exact* record: byte-level, version-bound, replayable through
  the real harness. When a rendered test and the engine disagree, this is the tiebreak.
  And for body-level panics/UB — a large share of real counterexamples — it genuinely
  does reproduce.
- Field rename to prevent the mistake by construction: `counterexample.kani_playback` →
  **`counterexample.kani_witness`**. §8's stability rule ("additive changes only after
  M3") permits this now and not later — do it in M3 or never.

## 5. Where it lives

- **Milestone M3** (its list already says "playback artifacts + rendered tests where
  possible" — this plan sharpens that line; wording delta 6 below).
- **Module**: `crates/ply-core/harness/` (§4 already assigns it "cex tests"), as a
  `contract_rt` renderer — §5.4a AST → overflow-safe runtime assertion code — with two
  consumers: the M3 cex test generator (concrete literal inputs) and the M4 test/fuzz
  harness generator (generated inputs). One renderer; the spike trap gets fixed once.
- **Depends on**: the E0501 subset validator's AST (M3), witness byte-vector decoding
  from the Ply-generated harness layout (M3), the D2 in-crate generated-module
  mechanism (M3), `old()` snapshot emission (shared with M4 per §5.4a).

## 6. How it gets tested

The test that would have caught the spike's finding — a violation that crashes nowhere,
so Kani's own playback test is green end to end and only an explicit contract assertion
can go red:

- **Fixture**: `fn clamp(x: u32) -> u32 { x.min(100) }` with
  `#[ply::ensures(result == x)]` — falsified at every x > 100; no overflow, no panic,
  anywhere, in body or contract.
- **`rendered_cex_test_fails_for_noncrashing_ensures_violation`** (e2e): run
  `cargo ply verify` on the fixture; assert a `ply_cex_clamp_*` test was generated;
  run `cargo test` in the fixture and assert (a) that test **fails** (exit code +
  per-test result), and (b) its failure output contains the contract text
  `result == x` and the word `postcondition` — asserting the *reason*, not just
  redness, so failing-for-the-wrong-reason cannot pass.
- **`rendered_cex_test_states_contract_not_overflow`** (e2e): the spike's own
  `saturating_bump` shape as a fixture; assert the generated test fails and its output
  does **not** contain `attempt to add with overflow` — the exact trap, pinned forever.
- Both then feed §9's existing oracle: apply the fix (body → honest contract, or
  contract → `result == x.min(100)`), re-verify, assert the test now **passes**.
- Golden: the generated test file itself is an insta golden (it is user-facing wording).

## 7. Spec deltas (wording written here, applied separately)

1. **D7** — replace the decision cell with:

   > Every counterexample is stored as **Kani witness data** (the exact input bytes,
   > engine-version-bound — input storage, not a reproduction: Kani's playback replays
   > the function body only and never re-evaluates contract closures, so an `ensures`
   > violation replays green) and, whenever the inputs can be rendered as stable Rust
   > source, additionally as an ordinary `#[test]` that **asserts the postcondition
   > explicitly** and therefore fails under plain `cargo test` — the only red artifact,
   > and D7's repair target. The assertion is rendered overflow-safe (widened/checked
   > arithmetic), so it fails by stating the contract, never by re-triggering an
   > incidental panic inside the check. When rendering fails, the diagnostic says so
   > (`W0541`) — inputs are never fabricated.

   Rationale cell: "Playback is exact but body-only (ADR-0003 caveat 3); the portable
   test is the agent-friendly repair target and carries the red-test promise alone."

2. **§1 finding 2** — after "where possible, a replayable test", add:

   > (the replayable test is Ply-rendered with the postcondition asserted explicitly;
   > engine playback data alone does not reproduce contract violations — ADR-0003).

3. **§0 terminology, "concrete playback"** — append: "Replays the harness and the real
   body only; contract closures are not re-evaluated, so a replay of an `ensures`
   violation passes. Input storage, not a reproduction."

4. **§8 schema** — rename `counterexample.kani_playback` → `counterexample.kani_witness`
   (pre-M3 rename, allowed once); replace the explanatory line with:

   > `kani_witness` is present whenever the witness-extraction step ran: the exact
   > failing input, byte-level and engine-version-bound. It is input storage — replaying
   > it exercises the body but does not re-check the contract, so it is never the
   > failing reproduction. `cargo_test` is that reproduction: present only when the
   > inputs rendered as stable Rust source (D7), else `W0541` with a `reason` of
   > `inputs_unrenderable` or `expression_unrenderable`.

5. **§8 example** — `"cargo_test"` path changes from `tests/ply_cex_pricing_quote_01.rs`
   to the in-crate generated module path (e.g.
   `crates/pricing/src/ply_generated/cex_quote_01.rs`), matching D2's mechanism.

6. **§9 cex validity oracle** — replace the sentence pair with:

   > every rendered `cargo_test` must FAIL under `cargo test` in the fixture before the
   > fix — with failure output that states the contract, pinned by substring — and PASS
   > after; every `kani_witness` artifact must *replay* under `cargo kani playback` with
   > the pinned version and its decoded inputs must equal `counterexample.inputs`
   > (replay is not required to fail — ADR-0003 caveat 3). A rendered test that does not
   > fail, or a witness that does not replay, is `X0902` (an adapter bug).

7. **§10 M3 bullet** — "playback artifacts + rendered tests where possible" becomes
   "witness artifacts (input storage) + rendered contract-asserting tests where possible
   (docs/plans/d7-replayable-tests.md); witness budget policy decided here".

Out of scope for this plan: any change to `tools/`, the spike, or the spec text itself;
u128 model-checking support; two-state specs beyond `old()`.

## 8. Witness budget — decided 2026-08-23

**Witnesses are generated for every falsified executable claim. Default is `all`.**
`--witnesses=N|none` exists as an explicit opt-out for someone who knowingly wants a fast
triage pass, and is never the default.

Rationale: §1's second finding is the reason this project exists — feedback without a
concrete failing input performs little better than none — and §1 states it as a MUST, not
a preference. A default cap would have silently violated that MUST for every finding past
the cap, producing exactly the unactionable "something failed somewhere" output Ply is
built to replace. The witness is not an optional extra on top of the finding; it *is* the
finding's evidence.

The cost is real and stays visible rather than being designed around: ~20s of near-fixed
overhead per failure (measured on a single-`u8` harness, versus 0.05s to detect). That
makes witness generation the dominant cost of a failing run, so it belongs in the progress
output ("generating witness 3 of 12…") and it is the first thing to optimise if it ever
becomes the bottleneck — by making it cheaper, not by skipping it.

When a user *does* opt out with `--witnesses=N|none`, the throttling must announce itself:
any finding whose witness was skipped says so in its own text and names how to get it
(`W0541` reason `budget_exhausted`). A finding that is witness-less for a *reason* and one
that is witness-less because the user capped it must never be indistinguishable.
