## Open work, ranked

### 1. Finish the container fix (this unblocks the last unchecked promise)

`record::fingerprint` is the one claim earning nothing. It is **no longer a field-count
problem** — that ceiling is gone. It has two list-of-struct fields, which is the shape whose
crash became an honest refusal in fix 4 above.

What is done: the gate looks inside a struct's fields, an enum's variant fields, and a
constructor's arguments, so the shape refuses honestly instead of crashing.

What is left, to make it *work* rather than refuse:

- The four places that resolve a field, a variant field, a constructor argument, or a route
  argument use a resolver that does not walk containers, so `Vec<Inner>` becomes
  `Vec<Unsupported>`. Route them through the container-walking resolver the top-level
  parameter path already uses.
- The leaf arm of the struct-building code likely needs to unwrap a composed expression when
  the leaf is itself a user type, or the field receives a raw tuple. **Believed, not
  confirmed** — check it.
- Turn the code-generation panic into a reported tool error, so a future disagreement
  between the gate and the generator can never take a whole run down again.

## Traps — read this part

**A fix can be worse than the bug. Check the shapes you did not think of.**
The first counterexample-scope fix (bug 3 above) made two cases worse than before: a claim on
a constructor-style function emitted a `use` naming a *type* as if it were a module — a hard
compile error where the old output built — and every nested claim whose promise named no
neighbour gained an unused-import warning, which is a build failure under `-D warnings`. Both
came from writing a second copy of a split the codebase already had correct.

**String-matching tests on generated code are worthless.** Two tests guarding that same fix
passed the entire time the generator was emitting a compile error. The test that replaced them
builds a real crate with warnings denied and asserts each shape fails on its *promise* rather
than its syntax. If you are testing generated code, compile it.

**Mutation-check the test, not just the code.** The replacement test above caught three of
four deliberate breakages; the one it missed was a case its fixture did not contain. The
first version of the wide-struct test had the same problem in a subtler form: the bug planted
in the fixture was too *rare* to be caught reliably. The fix was to make the threshold small,
so that a defaulted field would make the promise **hold** — the test now fails only when the
field is genuinely drawn.

**Ply's own reports catch weak promises. Read them.** Six promises were rewritten because
Ply's disclosure showed the boring half of an "either/or" decided 256 cases out of 256 —
random text is never valid input, so the half that mattered never ran. Where the interesting
case is genuinely rare, declare worked cases alongside the sampling rather than restating the
promise to hide the disclosure.

**Check an agent's base before trusting its output.** A 30-minute agent run produced 35
claims against a copy of the repo that had 6 claims instead of 44. Most duplicated existing
work, and it independently rediscovered two bugs already fixed that day. The genuinely new
findings were salvaged into TODO.md; the branch was not merged.

**Do not run the full workspace suite or the end-to-end tests casually.** CI is the authority
and the maintainer has asked twice for them not to be re-run locally. `cargo ply check` (about
a second) and targeted `cargo test -p <crate> --lib <filter>` are the working loop.
`cargo ply verify crates/ply-core` is minutes, and reuses recorded results.

## Quick orientation

```bash
cargo build --release -p ply-cli
./target/release/cargo-ply ply check crates/ply-core     # ~1s, no engines
./target/release/cargo-ply ply verify crates/ply-core    # minutes, reuses records
cargo run --release -p ply-render -- crates/ply-core/ply.yaml --text -o /tmp/out.txt
```

The text form is the one to read. About 95% of a drawing is in hover text, so reading the SVG
gets you a twentieth of the document with no way to know it.

To review a drawing, rasterise it **at its own size** and check the PNG came back that size —
CLAUDE.md explains why a square viewport silently truncates and reports success.
